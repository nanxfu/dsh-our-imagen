# ADR-0005：v1 不内置量化加载器，模型准入以实测为准

- 状态：已采纳
- 日期：2026-11-08
- 相关：[MODEL-CATALOG.md](../MODEL-CATALOG.md)

## 背景

T4 是 Turing 架构：有 INT8/INT4 Tensor Core，但**没有 FP8、没有原生 BF16**。扩散管线在 PyTorch/diffusers 下不会自动走 INT8 路径，量化收益不可假设。同时社区里流行的 FP8 权重与 NVFP4 权重在 T4 上直接不可用，Nunchaku 类 INT4 方案依赖 Ada 及更新的硬件。

## 决策

v1 只收录 fp16 能直接跑进 16GB 的模型；量化档（GGUF）延到 v1.1，且只服务"质量优先（慢）"档，默认折叠。任何模型卡进入工作台前必须跑完 B1~B6 六项基准并回填数字。

## 后果

- 默认体验保持"秒级"，不会被 20B 量化模型的分钟级耗时拖垮。
- 需要一个独立的基准脚本与一次真实内核运行，属于额外成本。
- 模型目录的表格存在 `待测` 状态，必须在 v1 收尾前清零。

## 备选与否决理由

- **v1 直接接 GGUF**：可以更早覆盖 Qwen-Image 这类大模型，但会引入第二套加载分支、权重下载更重，且首屏模型复杂度上升；与"简易工作台"的定位冲突。
- **按上游文档写 bfloat16**：T4 上会回退，属于错误配置，否决。
