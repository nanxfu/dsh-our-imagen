# 工作台交互语义对齐、双向助手闭环与现代模型演进规划

> **状态**：📝 已完成需求与方案对齐，待分期实施（2026-11-17）。  
> **前置基线**：0.13.0（已完成阶段十二「舞台图片处理工具栏解耦」与阶段十三「显式新建绘图、多作品草稿与树状版本管理」）。  
> **核心原则**：UI 保持克制、减少用户参数决策；表单—舞台—助手三向闭环；不给 SDXL 堆砌过时外挂技术债，优先挖掘和接入 2026 年原生多模态/单流 DiT 编辑能力。

---

## 一、 背景与第一性原理收敛

经过前十三阶段，工作台已经具备完整的文生图、局部涂抹、整图重绘、版本派生树（`⎇ N`）与 Agent 对话调用能力。在进一步对标主流同类产品与审视日常创作链路后，本阶段聚焦解决四类核心问题：

1. **交互语义与动作颗粒度尚未完全对齐**：
   - 舞台上的「生成变体 (`reroll`)」实际行为是“抄文字参数、换随机种子纯文生图”，与“变体”名不副实；舞台上的「带回参数 (`iterate`)」与点击胶片条自动回填高度重叠；画廊卡片同时存在切页面、盲发后台请求、放大预览等不同颗粒度按钮。
   - 在创作页选中已有作品并在左栏修改提示词/参数时，缺少“自动派生为新草稿、可自由切回看原图设置、可一键还原原图”的完整闭环（目前 `dirty` 会锁死胶片条回填）。
2. **表单、舞台与对话助手尚未真正打通**：
   - 参数表单一次生成 4 张图时，助手线程（`useChatThread.js` 的 `bubblePatch`）只展示第 1 张缩略图；
   - 舞台图片工具（`useImageTool`）的动作没有镜像同步进助手；
   - 点击助手里的结果图无法进入“单图聚焦上下文 + 返回上一层”的逐层迭代体验，助手也还看不见舞台当前图像。
3. **动作坞后处理闭环仍有缺口**：
   - `IMAGE_TOOLS` 中已预留的 `upscale`（高清放大）与 `outpaint`（扩图）尚处于规划占位状态。
4. **模型代差与技术债风险**：
   - 2026 年 SOTA 开源生图/修图已全面转向「单流/统一 DiT + 原生多图上下文（In-Context Editing）」；若在此时继续为 2023 年的 SDXL UNet 架构引入沉重的 IP-Adapter / ControlNet 插件栈，会在 Kaggle 2×T4 有限磁盘与冷启动时间下制造大量过时技术债。

## 二、 已对齐的产品交互与语义规范

### 2.1 术语、入口与画廊颗粒度收敛

| 入口位置 | 调整前 | 调整后（对齐方案） | 行为与语义说明 |
| :--- | :--- | :--- | :--- |
| **舞台动作坞 (`ImageDock`)** | `生成变体`、`带回参数` | 改名为 **`重新生成`**；**下线 `带回参数`** | `重新生成` = 使用当前作品提示词与参数、随机种子新抽 1 张纯文生图（产生新 `v1`）。点胶片条已自动回填，不再保留多余的「带回参数」按钮。 |
| **画廊卡片 (`GalleryCard`)** | `带回参数`、`生成变体`、`以此图重绘`、`查看大图`、`删除` | 收敛为：**`在工作台打开`**（点卡片图片亦同）、**`重绘编辑`**、**`查看大图`**（+ 收藏星标 / 删除） | **画廊不直接盲发后台生图请求**。所有后续创作与编辑动作统一在切回工作台并呈现进度流水线后执行，颗粒度完全统一。 |

### 2.2 左栏表单草稿流转与「还原原图」闭环

解决“改了一个词既不知道算不算新作品，又导致点回原图/其他图看不了原本设置”的卡点：

1. **查看作品 = 只读原图真相**：点击底部胶片条任意作品 `A`，舞台展示 `A`，左栏加载 `A` 的原始参数（干净基准）。
2. **一改词 = 自动托管进最左端「新建草稿卡」**：
   - 一旦在左栏修改 `A` 的任意提示词或参数，底部作品条最左端（复用 Stage 13 的 `newDraftCard` 位置）自动亮起 **`[ 未提交草稿 ]`** 卡片并实时托管该草稿。
   - 左栏顶部状态条显示：`正在新草稿中编辑（源自此图）`，并常驻轻量 **`[ 还原原图 ]`** 按钮（放弃当前改动，立刻恢复 `A` 的原始参数并清除左端草稿）。
   - *防闪跳细节*：正在 `A` 上输入修改时，右侧舞台保持展示 `A` 作为对照参考，不突然跳成空白取景框。
3. **自由看原图、不丢草稿**：
   - 因未提交修改已被左端「新建草稿卡」接管，此时点击胶片条上的 `A` 或 `B`，**系统不再拦截回填**——舞台与左栏安心展示 `A`/`B` 的真实原图与原始参数；
   - 点击最左端「新建草稿卡」，即切回新建取景画布并恢复刚才改到一半的草稿继续编辑或点生成发布；点草稿卡上的关闭/放弃即可丢弃草稿。

### 2.3 生图版本树语义边界（`src/logic/lineage.js`）

以后所有新增能力严格按**“是否有当前画布的像素级继承”**划分归属：

* **独立新根（`v1`）**：
  * 左栏纯文生图（含从旧图改词派生的草稿提交）
  * 助手新生成
  * **「重新生成」**（同参数换随机种子重抽，新构图不挂进原图版本树）
  * 未来的**「锁定主角 / 锁定画风画新场景」**（在 `meta.json` 记参考来源路径以便溯源，但不折叠进同一棵胶卷版本树，避免“雪山图”被藏在“咖啡馆图”下面）
* **派生子版本（`v2a` / `v2b` ...）**：
  * 仅限针对当前作品画布的原地二次加工：**`局部涂抹 (inpaint)`**、**`整图重绘 (img2img)`**、**`扩图 (outpaint)`**、**`高清放大 (upscale)`**。
  * 全部写入 `sourceImage` + `rootImage` 与加工类型，支撑版本派生树与「拉帘对比原图」。

### 2.4 跨面板双向时间线、单图钻取与「返回上一层」

把左侧助手页从“纯文字聊天框”升级为**“全工作台双向时间线 + 聚焦导航”**，同时严格保护大模型多轮上下文不被污染：

1. **多图网格反馈**：参数表单（或助手）一次生成 1~4 张图时，助手消息气泡（`bubblePatch`）完整接收全部结果图，以 **1~4 格缩略图网格** 呈现（修复目前只取 `images[0]` 的截断）。
2. **点击钻取与顶部返回条**：
   - 在助手网格中点击任意一张图（如第 3 张），右侧舞台同步选中该图，左侧助手进入针对该图的**单图聚焦上下文**；
   - 助手面板顶部出现轻量面包屑返回条（如 **`← 返回上一层（4 张生成结果）`**），支持点击逐层回到上一级结果网格或父版本，右侧舞台同步切回对应节点。
3. **舞台动作镜像同步**：
   - 在舞台发起「局部涂抹 / 整图重绘 / 高清放大 / 扩图」并提交后，助手线程自动追加一条镜像动作记录（含底图缩略图与动作说明，如 `对当前图发起了 局部涂抹`）和一条任务反馈气泡；
   - 生成完成后，助手气泡展示新版本图（`v2`）并附带**极简后续动作胶囊**（`对比原图`、`继续涂抹`、`高清放大` 等），点击结果图可继续向下钻取。
4. **上下文隔离约定**：
   - 表单同步卡与舞台镜像动作卡继续带有独立 `kind` 标记，**不进入**发给意图大模型的纯文本历史（`intentHistory()`）；
   - 仅当用户在聚焦态主动输入自然语言指令（如“把右边扩出去”或“分析一下这张图的提示词”）时，才把当前聚焦作品的图像与元数据作为当轮上下文传给宿主多模态 LLM。

## 三、 2026 现代模型策略与借用 DSH 宿主大模型原则

### 3.1 借用 DSH 宿主大模型（零额外 Key）与现状排查

* **唯一通道原则**：所有提示词润色、英译、意图解析以及未来的**多模态看图分析/指令路由**，全部复用 DSH 宿主提供的模型服务（`ctx.get('llm')` + `ctx.get('agentDefaultModel')`），不引入第三方 API 配置。
* **前置排查项（老问题优先修复）**：当前真实环境中「润色 / 转为英文」疑似存在静默退回本地兜底的异常，重点从以下两处入手定位修复：
  1. [index.js](file:///d:/document/development/our-free-imagen/index.js#L36) 中 `inject` 仅声明了 `['webServer', 'subprocess', 'tools']`，未将 `llm` 与 `agentDefaultModel` 声明为 Cordis 可选依赖，可能导致真实运行时 `ctx.get('llm')` 抛错或取不到后被 `lib/llm.js` 的 `try/catch` 静默吞掉；
  2. 核对 DSH 宿主新版 `llm.prepareCall` / `llm.stream` 的调用签名与分片格式，补齐可观测诊断日志（不再只记容易被忽略的 `debug` 日志而对失败原因失明），同时确认宿主传图的内容块格式。

### 3.2 2026 模型技术代差与算力适配策略

* **硬件基线约束**：Kaggle 默认提供 `2×Tesla T4`（16GB×2 Turing 架构，支持 `fp16`，**无原生 `bf16`/`fp8` 硬件加速**，容器每次重建约 20GB 可写空间）；规划中的路线图十四（Google Colab Pro `L4 24GB / A100 40GB`）则支持 `bf16`/`fp8` 与大显存单卡。
* **技术选型结论**：
  1. **保留 SDXL 作为 Kaggle T4 速度底盘，但停止新增 SDXL 专属重型外挂**：不在 2026 年专门为 SDXL 编写复杂的 IP-Adapter / ControlNet 权重加载与管理体系。
  2. **挖掘已内置的 `FLUX.2 Klein 4B` 原生参考与编辑潜能**：[flux2-klein-4b.json](file:///d:/document/development/our-free-imagen/models/flux2-klein-4b.json) 在 2×T4 上 `fp16` 实测峰值仅 ~7.9GB、4 步出图 ~10 秒；`diffusers` 中的 `Flux2KleinPipeline` / `Flux2KleinKVPipeline` / `Flux2KleinInpaintPipeline` 原生支持多图参考条件注入与上下文编辑。优先在 T4 真机验证其 `img2img` / 多图参考能力，用一个统一 DiT 底座承接一致性与指令编辑。
  3. **后处理尽量选择架构无关方案**：超分（`upscale`）独立于扩散模型底座；扩图（`outpaint`）由前端画布与蒙版生成逻辑抽象，远端在 SDXL 预设走已验证的 9 通道 `sdxl-inpaint`，现代模型预设可走其原生 Inpaint/编辑管线。
  4. **面向高阶算力的储备模型**：Kaggle T4 阶段可评估 `Z-Image-Turbo`（6B 单流 DiT，强化中文渲染与摄影质感，需测 `fp16` 稳定性）；待 Colab L4/A100 后端落地后，优先接入 **`FLUX.2 Klein 9B`** 与 **`Qwen-Image-Edit`** 实现真正的无蒙版语义级精准修图与高保真多图一致性。

## 四、 分阶段实施路线（Phase 0 → A → B → C）

### Phase 0：宿主 LLM 通道诊断与修复（地基清理）

* **目标**：确保「润色」「转为英文」「对话意图解析」在真实 DSH 环境中稳定调用宿主配置的默认大模型，摸清多模态传图接口规范。
* **主要工作**：
  - 核查并修复 `index.js` 的 Cordis `inject`（补充 `llm`、`agentDefaultModel` 可选注入声明）与 `lib/llm.js` 真实调用异常；
  - 增加 LLM 调用失败时的可诊断日志与来源反馈，保留离线单测全绿。

### Phase A：交互语义收敛、双向聚焦时间线与纯前端体验升级（零 GPU 风险）

* **目标**：彻底理顺“草稿/原图/重新生成/画廊”语义，打通表单—舞台—助手三向反馈与钻取导航，并上线零显存成本的高频辅助功能。
* **Phase A1（语义对齐与草稿闭环）**：
  - `ImageDock` 下线「带回参数」，「生成变体」统一改名「重新生成」；
  - `GalleryCard` 动作收敛为「在工作台打开」「重绘编辑」「查看大图」（及收藏/删除），移除画廊原地盲发生成；
  - 左栏编辑自动托管进最左端「新建草稿卡」，增加「源自此图 · 还原原图」并解除切换胶片条看原图设置的锁定。
* **Phase A2（双向时间线与聚焦返回栈）**：
  - `useChatThread` 支持 1~4 张图网格反馈卡；
  - `useImageTool` 提交/完成镜像同步至助手线程，结果卡带快捷后续动作胶囊；
  - 实现点击图钻取单图上下文 + 顶部 `← 返回上一层` 导航栈，严格不污染 `intentHistory`。
* **Phase A3（对比体验与多模态看图）**：
  - **拉帘对比原图**：所有带有 `sourceImage` 的派生版本（涂抹/重绘/未来放大/扩图）在舞台提供交互式对比滑块；
  - **PNG 元数据写入与拖入还原**：Host 写入标准 PNG `tEXt` 元数据块，支持将本地图片拖入工作台一键还原参数或设为编辑底图；
  - **多模态助手看图**：打通 `lib/llm.js` 的图像内容块通道，支持在助手中对当前聚焦图（或上传图）一键**反推提示词（Describe）**，以及通过自然语言由助手生成**图片工具确认卡**（整图重绘 / 引导涂抹）。

### Phase B：图像后处理闭环（点亮 `upscale` 与 `outpaint`）

* **目标**：激活舞台动作坞预留的两个工具位，补齐从“初稿生成”到“成片交付”的完整链路，并接入助手与 Agent 工具。
* **Phase B1 — 一键 2× 高清放大（`upscale`，`instant` 形态）**：
  - **前端**：动作坞点击「高清放大」零参数直接提交；完成后作为 `v2` 挂载进版本树，支持「拉帘对比原图」查看清晰度提升；
  - **远端**：接入轻量超分推理路径（如 Real-ESRGAN / Swin2SR），执行完毕按需释放显存，避免挤占常驻生成管线；
  - **真机验收**：在 Kaggle 2×T4 验证文生图 → 2× 高清放大的显存峰值、耗时与恢复能力。
* **Phase B2 — 快捷比例扩图（`outpaint`，`canvas` 形态）**：
  - **前端**：进入扩图画布态，顶部提供零计算快捷比例胶囊（`16:9` / `9:16` / `4:3` / `四边扩 20%`）与画框微调手柄，自动构造扩展画布与羽化蒙版；
  - **远端**：优先复用已验证的 `sdxl-inpaint` 9 通道管线（及后续支持的现代管线），按 8 对齐像素提交并产出 `v2`；
  - **助手联动**：支持用户在 `ChatPanel` 对聚焦图说“往右扩展一点”或“扩成 16:9 横屏”并生成扩图确认卡；同步评估在 `lib/tools.js` 补齐 Agent 侧图片后处理工具（如 `imagen_upscale` / `imagen_edit`）。

### Phase C：2026 现代模型级可控性与一致性

* **目标**：在不新增 SDXL 过时外挂债的前提下，实现极简的“锁定主角 / 锁定画风”创作与同角色批量分镜。
* **Phase C1 — `FLUX.2 Klein` 多图参考与编辑真机验收**：
  - 在 Kaggle 2×T4 实测 `Flux2KleinPipeline` / `Flux2KleinKVPipeline` / `Flux2KleinInpaintPipeline` 在 `fp16`（及按需 CPU offload）下的单/多参考图输入能力、显存峰值与步数耗时；
  - 同步调研 `Z-Image-Turbo` 在 T4 `fp16` 下的可行性。
* **Phase C2 — 极简「参考锁定」入口与助手批量分镜**：
  - 作品动作中增加「锁定主角 / 锁定画风」意向入口（底层不暴露复杂权重滑块，使用实测甜点配置）；
  - 锁定后左栏顶部展示紧凑参考胶囊，允许用户在左栏自由改词或切换场景生成新的 `v1` 独立作品，在 `meta.json` 记引用源但保持版本树清爽；
  - 对话助手支持“以当前图的主角批量生成 4 张分镜”（复用 `imagen_batch` + 参考图列表）；
  - 配合路线图十四（Colab L4/A100 后端）接入后，顺势引入 **`FLUX.2 Klein 9B`** 与 **`Qwen-Image-Edit`**。

## 五、 工程约束与验收门禁

1. **契约与字典同构**：所有新增路由、工具类型与参数边界必须先收口至 [shared/contract.js](file:///d:/document/development/our-free-imagen/shared/contract.js)（并同步 `remote/contract.json`）；中英字典（`src/dict/zh.js` / `src/dict/en.js`）保持键集合严格同构。
2. **离线与真机分层门禁**：
   - Phase 0 / Phase A：以 `npm test` 全套离线单测（契约、Host、Client 逻辑与渲染）+ 实际 DSH 环境联调验收为主；
   - Phase B / Phase C：每接入一项远端新推理能力（超分、扩图、`FLUX.2 Klein` 多参考），必须附带 `test/gpu-live.mjs` 在 Kaggle 2×T4 真机实测的耗时、显存占用（`/health.gpu_memory`）与成片质量复核，确认无 OOM 与显存泄漏后合入。
