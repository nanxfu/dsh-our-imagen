# 显式新建绘图、多作品草稿与树状版本管理规划

> **状态**：📝 规划中（2026-11-17）  
> **前置**：接续 [`ROADMAP.md` 第十二阶段](ROADMAP.md#十二-舞台图片处理工具栏与交互解耦规划中)（方案 B 舞台工具解耦落地后启动）  
> **目标**：把工作台升级为「**显式新建草稿 + 多作品独立草稿圆点 + 批与树状版本管理**」的创作空间，理顺多轮重绘、多图并排对比与版本回溯的心智模型。

## 一、核心产品模型

### 1.1 明确「新建绘图」语义
- **痛点**：当前「新建创作」只重置左栏几个字段，舞台上仍停着上一张旧图，用户分不清当前是在“改旧图”还是“从零画一张”。
- **改后体验**：
  1. 点击 **「新建绘图」** 进入显式新建态：右侧舞台切为**模糊动态背景 + 取景框**（明确告知“这是一张尚未生成的新画布”），左侧是干净的主表单；
  2. 底部作品条最左端（待执行区）出现一张**草稿预览卡**（显示当前草稿的画幅比例、预设标签与未提交态）；
  3. 填完参数点击生成后，草稿卡无缝转为排队/渲染卡片（`pendingJobs`）；**排队期间用户可自由点击底部作品切换浏览或对旧图进行编辑**，互不干扰。

### 1.2 切换作品保留草稿 + 圆点标记
- 基于第十二阶段解耦出来的舞台图片处理工具，将每个已有作品上的二次编辑状态按作品路径（`workKey`）独立保存：
  - 包括：未提交的**涂抹蒙版（`mask`）**、**重绘提示词**、**重绘强度/模型微调**。
  - **圆点标记**：只要某张作品上存有未提交的编辑草稿，底部作品条缩略图（及版本面板对应节点）亮起**状态圆点**，鼠标悬浮圆点可看到具体改动项（如 `已修改：涂抹区域 · 提示词`），并支持一键「清空该图草稿」。
  - **内存边界**：因蒙版 PNG base64 单张可达数百 KB～1 MB，会话内 `workDrafts` 采用 **LRU 缓存上限**（如最多保留最近 8 个含蒙版的草稿），超出时淘汰最久未编辑的草稿，避免内存无限膨胀。

### 1.3 「批（Batch）」与「树状版本（Version Tree）」概念
- **同一批（Batch）**：用户针对同一个表单提交一次生成的 `1~4` 张图片（如文生图 4 张 `[A, B, C, D]`），它们同属一个起始批次，在作品条上并排展示供挑选。
- **树状版本（Version）**：同一批下的每张图片都可以拥有各自独立的迭代分支；同时，针对某张图做重绘（`img2img` / `inpaint`）时也可能一次产出多张候选图。因此数据结构本质上是**树状派生**：
  ```text
  Batch #1 (同批 4 张起点)
  ├── A (v1)
  │   ├── A-v2a (局部重绘)
  │   │   └── A-v3 (继续涂抹)
  │   └── A-v2b (从 v1 再次分支)
  ├── B (v1)
  │   └── B-v2 (整图重绘)
  ├── C (v1)
  └── D (v1)
  ```
- **作品条折叠策略**：作品条按「根创作批次」占据主位（默认展示该树最新活跃节点或根缩略图 + 分支角标 `⎇ N`），避免连改几轮后作品条被 `v1 / v2 / v3` 迅速撑满。

### 1.4 作品集版本派生面板（Hover / 点击展开）
- **展示触发（防误触设计）**：
  - 仅在有派生版本（或正在生成派生版本）的缩略图上显示轻量分支角标（如 `⎇ 3`）；
  - 鼠标在缩略图上**停留超过短延迟（如 250ms）**或**点击角标**时，在上方稳定弹出**版本派生树面板**（使用 hover bridge + 延迟收起，避免鼠标从缩略图移入面板时闪烁消失；同时点击角标可固定展开，兼顾触控与键盘用户）。
- **面板内容**：
  - 树状展示该作品所在的完整上下游关系（含同批兄弟参考、子节点类型图标「涂抹/整图」、版本号 `v1/v2/...`）；
  - 实时呈现**草稿圆点**（哪一版上留着未提交草稿）与**在途幽灵节点**（哪个节点正在云端排队生成下一版）；
  - 点击树上任意节点即可把该版本切到右侧舞台预览，并直接基于该节点发起下一轮分支重绘。

## 二、涉及的状态全景（前后端 5 大域）

### 2.1 工作区焦点状态（Workspace Focus）
- `workspaceMode`: `'new_draft' | 'work'`
  - `'new_draft'`：显式新建绘图态（模糊动态舞台 + 底部新建草稿卡）。
  - `'work'`：浏览/编辑既有作品态。
- `selectedWorkKey`: 当前舞台展示的作品路径（`null` 表示处于 `'new_draft'`）。

### 2.2 新建绘图草稿状态（New Draft）
- `newDraft`: `{ active, prompt, negative, presetId, width, height, steps, cfg, seed, count, dirty, updatedAt }`
  - `active` 控制底部胶片条最左端是否显示草稿占位卡；
  - 提交任务入队后复位 `newDraft`，位置自然交接给 `pendingJobs` 中的排队卡。

### 2.3 按作品隔离的二次编辑草稿表（Per-Work Draft Map）
- `workDrafts: Record<workKey, WorkDraft>`（带 LRU 容量上限）
  - 单条 `WorkDraft`：`{ tool, prompt, negativePrompt, presetId, strength, strengthAuto, mask, changed: { mask, prompt, params }, lastTouchedAt }`
  - 派生 selector `workDraftSummary(workKey)`：驱动缩略图与版本树节点上的**圆点标记**与提示文案。

### 2.4 在途任务关联状态（In-Flight Jobs）
- `pendingJobs` 扩展溯源字段：
  - `sourceMode`: `'new_draft' | 'inpaint' | 'img2img' | 'variant'`
  - `parentPath` / `rootImage`：用于排队期间在版本树对应父节点下渲染「生成中节点」，且出图完成后自动归组到正确版本树，哪怕等待期间用户已切去看其他作品。

### 2.5 作品版本链持久化元数据（跨端 `meta.json` + `/history`）
- **现状复用**：[`lib/output.js`](../lib/output.js#L145-L149) 已在 `meta.json` 中记录单张图粒度的 `sourceImage`（即 `parentPath`）与 `inpaint`、`strength`，天然契合同批 4 张图各自建树的需求。
- **需补齐的后端字段**：
  1. `meta.json` 增记 `rootImage`（根作品路径，O(1) 归组整棵树；无此字段的老数据由前端按 `sourceImage` 链回溯推导）；
  2. `readHistoryItem()`（[`lib/output.js`](../lib/output.js#L206-L216)）向前端 `/history` 透传 `sourceImage`、`rootImage`、`inpaint`、`strength`；
  3. **跨分页防断链**：历史列表分页加载时，若当前页包含某棵树的子版本而根节点在更早页，后端支持按 `rootImage` 返回完整树或由 `/history` 按根批次聚合。
- **兼容兜底**：父作品被用户在画廊删除时，子版本自动提升为局部根或保留 `sourceDeleted` 标记，不造成树渲染崩溃。

## 三、分阶段实施路径（第十三阶段）

1. **Phase 1：后端版本链透传与 `rootImage` 落盘**
   - `validator.js` / `queue.js` / `output.js` 传递并写入 `rootImage`；`readHistoryItem()` 透传 `sourceImage / rootImage / inpaint / strength`；补齐单测与跨分页树拉取接口。
2. **Phase 2：显式新建绘图态与 `workDrafts` 多草稿圆点**
   - 实现 `workspaceMode`（模糊动态舞台背景 + 底部新建草稿卡）；
   - 将第十二阶段的 `useImageTool` 扩展为按 `workKey` 缓存的 `workDrafts`（带 LRU 上限），胶片条接入圆点标记与清除草稿入口。
3. **Phase 3：版本树归并、分支角标与版本派生面板**
   - 新增纯逻辑 `src/logic/lineage.js`（批与树状版本索引、`v1/v2` 编号、删除节点兜底、Ghost Node 挂载）；
   - 胶片条实现按根折叠 + `⎇ N` 角标 + 延迟 hover / 点击固定的版本派生树面板。
