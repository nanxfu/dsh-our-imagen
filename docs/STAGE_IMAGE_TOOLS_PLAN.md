# 舞台图片处理工具栏与交互解耦规划（方案 B）

> **状态**：📝 规划中（2026-11-17）  
> **前置**：接续 [`ROADMAP.md` 第十一阶段](ROADMAP.md#十一-状态流转与局部重绘可用性修复规划中)（状态安全与远端正确性修复完成后启动）  
> **目标**：将「文生图主表单」与「针对已生成作品的图片后处理」彻底解耦，建立以舞台作品为中心的统一图片工具栏，支持局部重绘一步直达，并为高清化、扩图等能力预留一致的交互框架。

---

## 一、为什么要做这次重构（第一性原理）

当前（`0.12.0`）将参考图与蒙版挂在左栏全局表单 `form.reference` 上，带来两个根本问题：

1. **心智模型倒置**：用户面对舞台上的作品，意图是**「我要对当前这张图做某种处理」**（涂抹改局部、整图重绘、高清放大）；现有流程却要求「先把图挂到左栏当参考图 → 回到舞台找涂抹入口 → 再回左栏改参数点生成」，路径过长。
2. **状态互相污染**：把图片二创状态混进文生图主表单，导致「舞台在看 A 图、左栏挂着 B 图参考图」、切胶片条误清参考图、对话助手/生成变体串台等一系列状态冲突。

**方案 B 的核心原则**：
- **左栏归左栏**：左栏主表单回归纯粹的「文生图 / 对话创作」面板，不承载历史作品的二次编辑状态。
- **舞台归舞台**：所有针对既有作品的动作（局部涂抹、整图重绘、未来的高清化/扩图），全部从舞台底部动作坞（`.ofs-dock`）就地发起、就地编辑、独立提交。

## 二、信息架构与交互设计

### 2.1 舞台底部动作坞（`.ofs-dock`）重组

将舞台底部按钮收拢为两类，保持克制、不堆砌：

| 分组 | 动作 | 行为 |
| :--- | :--- | :--- |
| **图片处理** | **局部涂抹** | 一步直达：以当前舞台作品为底图，原地切换为涂抹画布 |
| **图片处理** | **整图重绘** | 原地展开轻量重绘条（Prompt + 强度 + 生成） |
| **图片处理** *(预留)* | **高清放大** / 扩图 | 统一挂入此组（无参工具点击即执行，有交互工具进画布态） |
| **创作复用** | **带回参数** | 把当前作品的 Prompt/尺寸/参数回填进左栏表单（用于文生图再创作） |
| **创作复用** | **再画一张** | 纯文生图变体（显式不带参考图） |

> 注：`复制路径`、收藏、放大预览保留在图片右上角 `.ofs-figure-tools` 悬浮按钮中，让底部动作坞专注创作与处理动作。

### 2.2 「局部涂抹」一步直达流程

1. **触发**：用户在舞台（或大图预览）点击 **`局部涂抹`**，无需前置「以此图重绘」步骤。
2. **自动选模（不污染左栏）**：
   - 工具内部优先沿用当前模型（若支持 Inpaint）；
   - 若当前左栏选的是不支持 Inpaint 的模型（如 `flux2` / `anima`），工具内部自动选用默认局部重绘模型（如 `sdxl-inpaint` 或可用的 SDXL 预设）并在工具条内提示，**不改动左栏主表单的 `presetId`**。
3. **原地画布 + 内置轻量提交栏**：
   - 画布工具栏：画笔大小、橡皮擦、清空、反选、覆盖率读数。
   - 画布下方内嵌轻量提交栏：
     - **修改描述（Prompt）**：输入框（默认留空或可选填入原图 Prompt 片段，聚焦即可输入「把帽子换成红色贝雷帽」）；
     - **重绘强度（Strength）**：滑块（通用 SDXL 默认 `0.8`，`inpaintOnly` 默认 `0.9`，上限 `1.0`）；
     - **模型切换胶囊**（可选在支持的 Inpaint 预设间切换）；
     - **主按钮「重绘选中区域」** + **「退出」**。
4. **连续重绘**：生成完成、新图落到舞台后，新图底部同样有 **`局部涂抹`** 按钮；点击即可基于新图开始下一轮涂抹，自然闭环。

### 2.3 「整图重绘」轻量工具条

- 点击 **`整图重绘`** 后，在舞台下方展开轻量编辑条（不切画布，保留图片预览）：
  - 显示「正在重绘当前作品」标记、Prompt 输入框、强度滑块（`0.0 ~ 0.9`）、「生成」与「取消」。
  - 当前预设不支持 `img2img` 时，仅本次工具请求自动选用 `referencePresetOf()` 兜底预设，不改左栏表单。

### 2.4 统一扩展机制（面向高清化等未来工具）

后续新增图片处理工具时，统一按三类交互形态注册到 `.ofs-dock`：

| 交互形态 | 适用工具 | 交互方式 |
| :--- | :--- | :--- |
| `instant`（即时提交） | 一键 2x 高清放大、去背景等 | 无需额外输入，点击直接按当前图片提交任务 |
| `inline`（轻量参数条） | 整图重绘、风格迁移 | 舞台下方展开 1 行轻量控件（Prompt / 强度 / 档位） |
| `canvas`（画布编辑） | 局部涂抹（Inpaint）、扩图（Outpaint） | 舞台图片区切换为交互画布 + 底部轻量提交栏 |

## 三、状态模型与数据流解耦

### 3.1 新增独立状态域 `useImageTool`

将原本散落在 `useStudioForm` 里的 `reference` / `mask` 状态抽离为独立 hook（`src/studio/hooks/useImageTool.js`），表单 `useStudioForm` 不再持有任何参考图与蒙版状态：

```text
左栏主表单 (useStudioForm)          舞台图片工具 (useImageTool)
  - prompt / negative                - activeTool: null | 'inpaint' | 'img2img' | 'upscale'
  - presetId / width / height        - targetImage: { path, url, width, height }
  - steps / cfg / seed / count       - presetId (工具级独立选择，不回写主表单)
  ↓                                  - prompt / strength / strengthAuto
buildGenerateBody(form)              - mask: { data, coverage, digest } | null
  ↓                                  ↓
POST /generate (纯文生图)            buildImageToolBody(toolState) → POST /generate (带 reference / mask)
```

### 3.2 彻底消除既有状态冲突

| 原痛点 | 解耦后的表现 |
| :--- | :--- |
| 提交后点胶片条误清参考图/蒙版 | 胶片条只服务左栏回填；与舞台工具完全无关 |
| 对话助手 / 生成变体带出旧蒙版 | 左栏与对话助手永远不读 `useImageTool`，天然纯文生图 |
| `sdxl-inpaint` 选了但没图导致生成按钮被拦 | `inpaintOnly` 模型不再暴露给纯文生图主表单选择器（或仅作为局部重绘工具的可选底座），主表单永远能正常文生图 |
| 连续重绘忘记换参考图 | 每次点舞台上的「局部涂抹」，底图永远绑定当时正在看的那张图 |

### 3.3 编辑态下的胶片条与任务提交行为

- **编辑中切换胶片条**：若用户正在涂抹画布（`mask` 非空）时点击右侧胶片条，弹出轻量提示或要求先退出涂抹态（避免未提交的笔迹无声丢失）；普通预览态下点击胶片条自由切图、自由回填左栏。
- **提交与并发**：工具提交后进入统一的队列任务流水线（`activeJob`），提交成功即可收起编辑器回到舞台等待新图落定；任务失败时，可从 `toolPendingRef` 完整恢复底图、Prompt 与蒙版并重新打开编辑器供重试。
- **远端与契约复用**：远端 `daemon`、`reference_codec.py`、`validator.js`、第十一阶段落地的 `inpaintMax = 1.0`、羽化自适应、空蒙版拦截等能力**全部原样复用**，本阶段几乎只改前端状态层与舞台组件。
