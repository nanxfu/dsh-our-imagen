# 工作台双向同步与创作流转设计参考 (STUDIO_SYNC_AND_ITERATION_DESIGN)

> **文档定位**：本文档整理「参数表单 ↔ 创作助手同步」「胶卷点击加载参数」「版本微调与新建创作边界」四项交互改进的意图、产品决策与约束边界，供后续 Coding 专员落地参考。
>
> **关于自主权**：文档只对齐要解决的问题、已拍板的产品取舍和边界条件，不规定具体的组件拆分、状态字段命名、CSS 样式写法或提示词措辞。Coding 专员可以根据当前代码结构自主选择最干净的实现方式。

---

## 一、 背景：为什么要理顺这几件事

0.10.0 把创作助手和参数面板的分工理顺了（助手负责从 0 到 1 起草，表单负责从 1 到 N 调参抽卡），但实际用起来还有几处体验割裂：

1. **表单生成会同步进助手，但行为和展示都比较粗糙**：表单点生成后，助手线程里会多出一条纯英文提示词气泡，既看不到模型/比例/分辨率等关键信息，也会把表单提交混进多轮对话历史里；同时右上角叫「清空对话」，给人感觉像在删记录，而不是开一个新主题。
2. **创作区点胶卷只换大图、不带出参数**：在画廊里点图只是浏览，不动表单很合理；但在创作区底部胶卷里来回切图时，人往往是想看这张图的参数、接着微调，每次都要再点一次「带回参数」多了一步。
3. **「微调旧图」和「新建创作」没有明确边界**：一旦支持点胶卷自动带入参数（包括原图 seed），就必须让人清楚自己现在是在微调某张图，还是在重新画一张新图，否则很容易带着上一张的 seed 或参考图继续生图。

---

## 二、 四项改进与已确认的产品决策

### 1. 「清空对话」改为「新建对话」（开启新上下文）

- **现状**：`useChatThread` 只有一个内存消息列表，操作按钮文案为「清空对话」（`studio.chat.clear`）。
- **改动方向**：
  - 将操作语义与文案调整为「新建对话」（如 `新建对话` / `New chat`）。
  - **已确认范围**：点击后只需**清空当前线程、开启新的对话上下文**即可，本轮不需要做多会话历史列表或切换归档（注意如果当时正处于意图解析中，点新建对话需要安全复位解析状态，避免旧请求回来写进新上下文）。

### 2. 表单同步到助手：细粒度参数展示 + 不污染 LLM 上下文

- **现状**：从 `Rail` 提交生成时，`useStudio` 会往 `chat` 推一条普通 `user` 消息（内容只有 `body.prompt`）和一条 `job` 气泡。这带来两个问题：
  1. 助手流里看不到这次是用什么模型、什么比例/分辨率、几张、有没有垫图；
  2. 这条 `user` 消息会被 `intentHistory` 当成用户说过的话传给大模型，如果用户在表单里顺手跑了一张别的题材的图，会带偏助手接下来的多轮理解。
- **改动方向**：
  - **细粒度展示**：表单同步进助手时，除了提示词文本，一并带出这次生成的关键参数摘要（如模型名、画幅比例与像素尺寸、生成张数、是否使用了参考图、是否锁定了特定种子等），用紧凑的标签或胶囊形式呈现，不要铺成大段文字。
  - **上下文隔离**：这类由表单提交同步过来的记录，在视觉上和普通自然语言气泡有所区分，且**不要进入** `intentHistory` 传给意图解析模型（除非后续有意做“把某次表单记录拉回对话继续改”的显式入口，本轮先保持上下文干净）。

### 3. 创作区（胶卷）点击自动加载参数 + 草稿保护

- **场景区分**：
  - **画廊（`Gallery`）**：保持纯浏览心智，点击卡片只看图，不自动改写左侧工作台参数（「带回参数 / 以此图重绘」仍作为显式按钮存在）。
  - **创作区胶卷（`Filmstrip`）**：在创作视图下点击胶卷里的图片切换预览时，默认把该图的参数同步加载到左侧参数面板。
- **已确认的 Seed 策略**：
  - **保留原图 Seed**（只要该作品记录了有效的非负 seed，就一起填入表单；没有记录则保持随机）。这样“你在看哪张图，表单就如实还原那张图的参数”，语义一致，方便直接微调同一构图。
- **已确认的草稿保护策略**：
  - 直接覆盖最怕误杀用户正在手写的提示词或刚调好的参数。因此需要区分表单是否处于**「有未提交的手动修改（dirty）」**状态：
    - 当表单是干净的（刚打开、刚生成完、或刚从另一张图加载完未作改动）时：点击胶卷切换图片，直接加载该图参数，无需打断。
    - 当用户已经在表单里手动改过内容、且还没有点生成时：点击胶卷**仍然正常切换右侧预览大图**，但**保留左侧草稿不被覆盖**，并给出一条轻提示告知用户“已保留当前草稿”（用户若确实想覆盖，仍可通过大图上的「带回参数」显式覆写）。
- **关于图生图残留的细节**：
  - 通过胶卷加载或「带回参数」回填一张普通作品时，注意清理掉表单里可能残留的上一轮参考图（`reference`），避免上一轮垫图状态串到另一张纯文生图作品的微调里。

### 4. 明确「版本微调」与「新建创作」的行为边界

当“点击胶卷会带入原图参数和 Seed”成为默认行为后，面板里很容易残留上一张图的 `seed`、`reference` 或排除项，导致用户想画新主题时被旧状态绑住。需要在交互上把两种状态区分清楚：

| 状态 | 语义 | 典型触发方式 | 表单表现 |
| :--- | :--- | :--- | :--- |
| **版本微调** | 基于某张已有作品继续调词、改步数或换构图 | 点击胶卷缩略图、点画廊「带回参数」或「以此图重绘」 | 完整还原该图参数（含原图 Seed；若是重绘则挂载参考图）。建议在面板合适位置给出轻量状态提示（例如提示当前正在基于某张作品微调），让用户知道 Seed/参数不是空的。 |
| **新建创作** | 撇开当前作品，从一个干净的起点重新画新图 | 点击面板提供的「新建创作 / 重置」入口 | 清空提示词、**清空参考图**、**Seed 恢复为随机**、排除项回到当前预设的默认推荐状态，并清除微调来源标记与 dirty 状态。 |

> 提示：新建创作时，当前选中的**模型预设**和用户常用的画幅比例可以保留（不必每次重置都把模型打回默认预设），重点是把“绑定到上一张具体作品”的状态（提示词、参考图、固定 Seed、微调来源标记）彻底清干净。

## 三、 落地时的注意事项（工程约束）

1. **中英字典同构**：涉及新增或修改文案键时，`src/dict/zh.js` 和 `src/dict/en.js` 保持严格同构，并跑通 `npm run test:client`（含文案检查、逻辑测试、渲染测试）。
2. **既有测试兼容**：`test/check-client-render.mjs` 中存在对旧文案（如 `清空对话`）的断言，改动文案时需同步更新对应断言并补充新交互（草稿保护、新建创作、表单同步不进 `intentHistory` 等）的测试覆盖。
3. **纯函数与 Hook 边界**：判断 `intentHistory` 过滤、参数回填/重置补丁等逻辑尽量留在 `src/logic/` 方便离线单测，UI 状态（如 `dirty` 标记、微调来源提示）留在 `src/studio/hooks/` 内管理。
