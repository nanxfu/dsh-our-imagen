# 工作台界面（WORKBENCH-UI）

本文定义界面落点、信息架构、引导分镜、状态矩阵与交互细节。所有 slot 名称需在真实页面上复核一次（事实调查时页面未连接，slot 树未能拉取；当前清单来自已装插件源码）。

---

## 1. 落点

| 用途 | slot | 备注 |
| :--- | :--- | :--- |
| 主工作台 | `sidebar.right.pane.tab` + `sidebar.right.pane.tab.title` | 常驻右侧面板，宽度足够放 2 列模型卡与图墙 |
| 退化入口 | `settings.section` | 右侧面板不可用时自动启用，内容为同一组件的整页布局 |
| 状态徽章 | `conversation.session.header.utilities` | 显示状态点、会话时长、一键关机、未就绪红点 |
| 备选徽章位 | `conversation.composer.dock` | 会话头 slot 不可用时启用 |

退化判定：注册右侧面板后探测挂载结果；未挂载则注册 `settings.section`，并在徽章里提示"工作台入口已移至设置页"。判定只做一次，结果记在内存，避免重复注册。

## 3. 模型卡显示项

每张卡从上到下固定七行，顺序不随卡片宽度变化：

1. 预设名 + 一句质量定位（"极速草稿"/"质量优先"）；
2. 许可徽章（绿：Apache/MIT；橙：非商用或 `license: other`）+ gated 标记；
3. 权重体积与所需卡数（`15.2GB · 需 2 卡`）；
4. **首次约 X 分钟**——含下载与加载，括号内注明其中下载占多少；
5. **会话内切换约 Z 秒**——同会话换模型只重载，不重下；
6. **出图约 W 秒**——稳态中位，展开可见实测区间；
7. 状态标记（可用 / 需双卡 / 加载 OOM）。

第 4、5、6 行必须来自 [MODEL-CATALOG.md](MODEL-CATALOG.md) 的实测列，未实测时显示 `待测`，**不得用上游宣称值顶替**。卡片默认只显示三行摘要（名称、许可、首次分钟数），展开后给完整七行，避免图墙被数字淹没。

## 4. 引导分镜（首次加载）

面板内分步引导，不弹浮层；任何一步都可回看。四步：

**第 1 步 · 环境检查**
检测 `kaggle` CLI 是否存在、版本号；缺失时给出 `pip install -U kaggle` 与"我已安装，重新检查"。
动作：`重新检查`。

**第 2 步 · 账号接入**（主路径：API token；兜底：OAuth）

主路径——用户自己把 token 写进 CLI 的凭据位置，插件全程不接触 token：

1. 面板给出入口链接 `https://www.kaggle.com/settings/api`（Generate New Token）与一句话说明"token 只显示一次"；
2. 提供一条可复制的命令，用户把 token 粘进去后在终端执行：

   ```powershell
   Set-Content -NoNewline "$env:USERPROFILE\.kaggle\access_token" "在这里粘贴你的token"
   ```

3. 用户回来点"重新检查"，插件执行一次 `kaggle kernels list --user <账号> --page-size 1` 做真实验证（**不用** `kaggle auth login` 的本地回显，也不用 `quota`，后者长期不可用）。

兜底——OAuth 托管登录（token 方式失败，或用户偏好 OAuth）：

1. 插件托管 `kaggle auth login --force --no-launch-browser`（`stdio: { stdin: 'pipe', stdout: 'pipe', stderr: 'pipe' }`）；
2. 从 stdout 解析授权链接，渲染为"在浏览器中授权"按钮；
3. 用户在浏览器拿到一次性验证码，面板输入框收下后写入子进程 `stdin`；
4. 子进程退出码 0 → 再用一次真实 API 调用复核。

约束：验证码只存在于内存，不落盘、不进日志、不回显；子进程超过 5 分钟或面板关闭即终止；重试前必须先杀掉残留子进程。

失败处理：若检测到 OAuth 残留凭据干扰（OAuth 与 token 并存时 CLI 的优先级未实测），提供"清理残留后重试"的可选步骤，并说明这会撤销当前 OAuth 登录。

**第 3 步 · 加速卡确认**
说明：账号未完成手机验证时，Kaggle 会静默把任务降级到 CPU。
动作：`我已确认` / `去验证（打开 Kaggle 设置）`。
判定：无法在不启动内核的情况下确证，故本步以用户确认为准；真正的降级检测在首次启动时由 `cpu_fallback` 错误兜底。

**第 4 步 · 就绪**
展示当前配额、默认模型卡、预估首次启动耗时（排队 + 权重下载 + 加载；实测排队可达十余分钟，文案不得承诺"2~3 分钟"）。动作：`启动 GPU 并生成第一张`。

## 5. 状态矩阵

| 会话状态 | 资源条 | 参数区 | 生成按钮 | 图墙 |
| :--- | :--- | :--- | :--- | :--- |
| `absent` | 灰点 + "未启动" | 可用 | 显示"启动并生成" | 空态文案 |
| `provisioning` | 呼吸点 + "排队中，可能十余分钟" + 计时 | 禁用 | 禁用 | 空态 |
| `booting` | 呼吸点 + "启动中，约 2~3 分钟" | 禁用 | 禁用 | 显示上次结果 |
| `ready` | 绿点 + 会话时长 + [关机] | 可用 | "生成" | 可浏览 |
| `busy` | 绿点 + "生成中 i/n" | 禁用 | 变为"取消剩余" | 占位卡动画 |
| `failed` | 红点 + 错误摘要 | 依错误而定 | "重试" | 保留历史结果 |

资源条的配额位有两条呈现路径：配额可得时显示 `已用/总量 + 重置时间`；不可得时（当前 CLI 的常见情况，见 [PROTOCOL.md](PROTOCOL.md) 第 6 节）降级为 `配额不可用 · 诊断`，原文收进诊断区，其余位置继续显示会话计时与显存。

错误态必须包含：一句人话归因、一个主按钮、一个可展开的诊断区（日志尾部 60 行）。

## 6. 生成中的动态表达

- 每张待生成的图占一个占位卡：底色渐变 + CSS 呼吸动画（`opacity` 与 `transform` 的 1.6 秒循环），**不引入 GIF/Lottie 资源**。
- 占位卡内显示：序号 `i/n`、当前已耗时（每秒刷新）、当前阶段的简短文案（"排队中""加载模型""生成中"）。
- 完成后占位卡原地替换为图片，用 120ms 的淡入，不重排布局。
- 资源条同步显示"生成中 i/n"，徽章用同色呼吸点。

## 7. 图片呈现

- 服务方式：`GET /imagen-api/img?id=<jobId>&n=<index>`，返回 `image/png`，`cache-control: private, max-age=300`。
- 客户端 URL 必须基于 `document.baseURI` 构造（反代前缀下裸 `/api` 会 404）。
- 缩略图：列表用原图 + `loading="lazy"` + `decoding="async"`；单张 1MB 量级无需额外转码。
- 点击图片打开大图浮层，附参数与"复制 seed""在文件夹中显示"。

## 8. 轮询与性能

| 会话状态 | 间隔 |
| :--- | :--- |
| `booting`、`busy`、`provisioning` | 2 秒 |
| `ready`、`absent` | 10 秒 |
| 页面不可见 | 暂停（`visibilitychange`） |

单次轮询响应控制在 4KB 以内：状态接口只返回摘要，不含图片与完整日志。

## 9. 文案与国际化

- 命名空间 `our-free-imagen`，语言 `zh` 与 `en`。
- 术语统一：会话 / 配额 / 模型卡 / 引导 / 产物。
- 面向用户不出现内部代号（如 `kernel_id`、`ntfy`），诊断区除外。
- 错误文案模板：`<现象>。可能原因：<归因>。下一步：<动作>。`

---

## 10. 可访问性与细节

- 全部交互可键盘完成：`Enter` 提交、`Esc` 关闭浮层、`Tab` 顺序遵循视觉顺序。
- 呼吸动画遵循 `prefers-reduced-motion`，降级为静态描边。
- 生成按钮在 `busy` 态变为"取消剩余"，不做隐藏，避免布局跳动。
- 空态必须给出下一步动作，不留纯插画。
